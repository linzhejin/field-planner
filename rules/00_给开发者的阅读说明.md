# 农时窗口规则与资料开发交接

交接日期：2026年10月17日。本包供金鳞哲接入开发使用，包含候选规则、依据原件、接口约定和参考算例。当前没有可运行的Agent，也没有实际Agent性能或田间验证结果。

## 建议阅读顺序

1. 阅读“农时窗口_规则卡片_融合修订版_20261017/先读我.md”，明确当前规则版本和首版范围。
2. 阅读同目录“农时窗口_规则卡片表_融合修订版_20261017.docx”及“新增资料审查与补充说明.md”。核心31张卡保持原版；新增4份资料通过补充说明关联原卡。最初12份与新增4份合计16份PDF均随包提供。
3. 阅读“农时窗口_规则与验证交付包_20261017/02_规则验证与开发交接.docx”，理解状态、输入输出、排程和反馈重排。
4. 接入结构化JSON并运行校验。需要逐句追溯时再查原件；不必先通读所有PDF。

## 首版开发范围

湖北已确认进入苗期的油菜，三块地、未来七天，两类核心任务为巡田苗情检查和沟渠检查维护，也可接收用户已确认的其他待办。资料提供候选建议；需求、执行条件和资源约束分别确认，再进入排程。

首版候选共7张：C11、C18、C19、C20、C23、C24、C31。它们不等于7项必做任务，同地同次巡田应合并检查项。所有卡片的 `runtime_enabled` 当前均为 `false`，代表尚未配置采用；本交接不自动开启任务执行。

## 接入时保留的边界

- 适用性、维护需求、逐日作业窗口和实际排程状态分别记录。未知保持未知；已确认无需求不生成维护任务。
- 检查前不知道苗情、积水或虫情，不妨碍提出检查候选；具体日期仍需天气与现场作业条件确认。
- 人力不足不改变农业作业窗口；已完成任务的历史事实不随重排改写。
- 原文里的地区、年份、生育期及田况要随引用保留；不把地方参数统一成全湖北硬阈值。
- 不自动生成药剂处方、精确施肥或复杂机械调度；病虫名单不是诊断，降雨预报不是地面积水实况。

## 如何校验

解压后保留三个资料目录与“校验全部资料.py”的相对位置。在 `rules` 目录打开终端，使用Python 3.10或更新版本：

```text
python -m pip install -r requirements.txt
python 校验全部资料.py
```

依赖清单记录了打包时实际验证所用版本。安装依赖通常需要联网；依赖齐全后，校验本身只读取本地文件，不下载资料。

“资料校验结果.json”汇总两包结果；每包另有自己的“校验结果.json”。失败返回非零退出码，并记录原因。本包已检查原件指纹、引用页码、31张卡与Word一致性、47段融合包引用、参考计划和错误反例。这里的“通过”只表示资料与算例内部一致，不能作为Agent效果或农业有效性结果。

来源索引的 `file` 或 `local_original` / `read_path` 是实际使用的相对路径。`original_snapshot` 中整理者电脑的绝对路径仅记录历史来源，不是运行依赖。不需要旁边的Claude目录、临时生成文件或整理者的Python安装路径。

“结构化资料/内容校验记录.json”保留最初31张卡和29页Word的复核基线，其中12份来源是历史版本数量；当前16份来源及新增审查的状态看最新“校验结果.json”。修改核心规则或Word后需要同步内容和重新复核，不能仅改指纹使校验通过。
