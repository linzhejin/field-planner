# 农时窗口产品对齐与验收 Implementation Plan

> **For agentic workers:** Use subagent-driven-development for isolated implementation/review tasks; the coordinating agent integrates and verifies the complete user flow. No commit or publication is authorized.

**Goal:** 修复本次审查的七个缺陷，完成八项交互差距及视觉整理，并逐项提供 review、自动测试和浏览器证据。

**Architecture:** 保留 Streamlit、WorkbenchServiceV3、SQLite 事件与计划版本结构。时间与事实语义在服务层校验，页面只管理编辑草稿、对话框和当前操作；展示文案使用统一中文转换。

**Tech Stack:** Python 3.12、uv、Streamlit、Pydantic、SQLite、pytest。

## Global Constraints

- 保留现有用户数据、完成记录原事件、旧计划与规则原件；更正通过显式事件进行。
- 使用北京时间；未知条件不能被默认填成可作业；计划采用必须由用户确认。
- 单人、每地独立排程；联合排程、其他待办、拖拽继续暂缓。
- 候选规则继续标记“开发验证，适用性待复核”；不声称农业专业验收完成。
- 不提交、推送或发布；不添加生产依赖；测试使用隔离数据库。

## Task 1: 可靠性缺陷

- [ ] 先写失败测试：今天的新任务不得排进过去；保留完成项原时段；已采用的完成事件可显式更正/撤回，原事件保留；普通修改不得解除完成锁。
- [ ] 新排程以服务注入时钟为下限；离线回放使用显式时钟，避免依赖运行机器日期。
- [ ] 改起始日按绝对日期保留交集，新增日期的现场/天气/人员条件为空；不搬移日期确认。
- [ ] 页面只渲染一个可采用预览；关闭对话框清除打开状态；新增第二块地可取消并返回。
- [ ] 手动预览刷新可恢复；过期预览不能采用，明确重算入口；重复点击不产生重复版本。
- [ ] 运行相关测试及独立 review，解决高/中优先级发现。

## Task 2: 交互闭环

- [ ] 七天按日分组，空日期显示暂无安排；未排入、待确认、完成分别展示；持续显示跨地块未统筹提示。
- [ ] 任务详情直接记录完成、修改指定日期/时长/优先级、取消未完成任务并保存原因；日期修改仍经过条件校验。显式更正完成入口保留原事件。
- [ ] 历史支持选择版本、查看完整安排/依据/输入与版本差异；恢复旧安排只产生按当前事实校验的新预览。
- [ ] 最多三个中文缺项问题，提供对应补充入口和暂时跳过；跳过按档案/事实版本记住，不修改未知事实。
- [ ] 明确起止日期的批量条件与时段编辑，提交前展示范围与确认依据，未知为默认。时段可推导分钟数，允许用户限制总工时。
- [ ] 编辑草稿与确认档案分开；关闭/切换保留编辑内容，显示未保存、继续编辑、放弃编辑；保存失败保留输入。
- [ ] 真实模型/工具阶段回调、失败重试与结构化入口；不伪造进度，取消/离开不迟到写入。
- [ ] 为上述关键行为补测试并 review。

## Task 3: 视觉与可用性

- [ ] 首次建档使用宽主区；已有计划桌面三栏约 20/52/28，窄屏页签。
- [ ] 顶栏紧凑，统计始终一行；首屏优先下一步和任务；统一深绿操作、琥珀待确认、灰红异常。
- [ ] 主界面去除内部字段、UUID、英文变更类型与冗余说明；技术内容收进详情。
- [ ] 同一场景突出一个主操作；键盘焦点、正文和标签可读；空、成功、失败、取消、重试都明确下一步。

## Task 4: Review 与验收

- [ ] 全量 pytest、ruff check、ruff format --check、check_env；保留失败到通过的证据。
- [ ] 浏览器验证空白建档、第二块地返回、日期调整、预览采用、关闭弹窗后历史、任务修改/完成/更正、刷新恢复、导出、窄屏。
- [ ] 独立 review 全部 diff，修复并复核发现。
- [ ] 更新 README 和本轮验收报告，列出逐项证据与仍需真人体验/农业复核的边界；旧评测成绩不覆盖。
