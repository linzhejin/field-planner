# 内部封存自动验收 v1

本协议用于内部阶段验收，不将案例结果换算为比赛分数。仓库官方竞赛规则第 2 页按创新性 25、需求分析 15、AI 技术应用 20、项目实施 15、应用成效 15、总结展望 10 评价整个作品；以下检查仅为可复现的实施证据。正式输入为 30 个主案例（正常 8、缺项 6、冲突 6、反馈 6、不适用或失败 4）和 6 个边界案例。A 为直接生成，B 为同条件检索增强，C 为完整 Agent；主案例各运行一次，共 90 份，边界只运行 C，每例三次，共 18 份。每次使用新 SQLite 数据库、固定案例时钟和天气快照。

## 运行前准备

四份 UTF-8 JSONL 分别保存主案例、主参考约束、边界案例、边界参考约束，按 `case_id` 一一对应。主案例 `classification` 固定使用 `normal`、`missing`、`conflict`、`feedback`、`inapplicable_or_failure`。不得把参考约束放进模型输入。正式案例须有 `interaction_script` 中的 `chat` 步骤，约束须包含该步骤的 `required_tool` 断言。旧案例的维护目的未知时保持 `null`，对应预期保留待确认；不能为使程序通过补造目的。

每条约束需写明 `basis`（产品范围、来源原文或工程约定）、`required_tasks`（任务类型及允许状态）、`forbidden_task_types`、`required_missing_fields`、`citation_required_task_types`、`semantic_required`、`c_only_assertions` 和 `allowed_execution_statuses`。例如巡田可允许多个合法时段，只断言 `{"task_type":"inspection","allowed_statuses":["scheduled"]}`；完成、反馈和引用另写独立约束。正式约束须在首次运行前人工核对输入矛盾、来源位置和允许的非唯一答案。程序仅检查字段和可执行断言，不能证明案例由独立人员编写。

封存运行时，C 组的天气搜索和查询工具只读取案例快照，不连接实时天气接口；B/C 的规则检索使用同一条件和资料版本。封存前提交干净代码。以下路径均应在**仓库外**，本地密钥只在被忽略的 `.env` 中：

```powershell
uv run python -m nongshi.d02_sealed seal --main-cases D:/eval/main.jsonl --main-constraints D:/eval/main_constraints.jsonl --boundary-cases D:/eval/boundary.jsonl --boundary-constraints D:/eval/boundary_constraints.jsonl --exposure-log D:/eval/exposure.json --output-dir D:/eval/seal-v1 --env-file .env
uv run python -m nongshi.d02_sealed run --seal D:/eval/seal-v1 --env-file .env
uv run python -m nongshi.d02_sealed prepare-review --seal D:/eval/seal-v1
uv run python -m nongshi.d02_sealed judge --seal D:/eval/seal-v1 --env-file .env
uv run python -m nongshi.d02_sealed score --seal D:/eval/seal-v1
```

`seal.json` 锁定输入、约束、依赖、规则资料、模型配置和代码提交的 SHA-256。封存目录非空、代码有改动、数量不符或指纹变动时拒绝运行。`first_attempts.partial.jsonl` 与私有组别映射逐条写入；最终记录另写 `run_integrity.json` 指纹，评分前复核。中断后不得把旧记录当作新首次运行。修复或勘误建立新版本，并保留旧分及全部组受影响记录。`--development` 仅用于公开题验证，输出永远标记为开发数据。

## 判定口径

程序独立核对时间重叠、连续时段、工时、期限、前置、现场与天气确认、反馈后的资源、完成记录和重复任务，不调用被测排程器判分。参考约束检查必需与禁止任务、关键缺项和 C 专属流程。已安排且要求引用的事项必须有规则号、来源号、页码、原文和用途；暂缓资料不能直接支撑处置。语义复核视图不含组名、调用次数、耗时或工具日志；若用同一家模型，报告为“同服务商 AI 辅助复核”，不称独立专家评审。

每个断言保存通过、失败、不适用或待复核及原因。不适用须在约束中预先确定；错误输入、接口失败和未完成结果保留在分母。C 的自动验收仅在必需断言全通过、硬违规为 0、引用完整、语义支撑率至少 95%、严重无依据建议为 0 且无关键待复核时通过；有确定失败则未通过，否则为证据不足。报告并列展示 A/B/C 分项通过率、请求与工具数、token、耗时中位数和 P95；费用未知记为未知。边界同时展示 18 次通过数与 6 题三次全通过数。

目前公开仓库只有加密候选交接包，未获可用口令或解密文件时不能运行 90＋18，也不能把开发样例称为正式封存成绩。D01 原有双人独立评分要求仍单独待办；此协议只形成“内部封存自动验收”证据。
