## 为什么在仓库加密保存

本仓库公开，开发方也可读取。公开候选题或参考约束会破坏后续留出隔离。因此仓库只公开数量、状态与交接方法；完整内容按角色加密归档，三包使用不同口令，口令由李思默在仓库外分别交接。不要把口令、解密后的ZIP、输入JSONL或参考材料重新提交仓库。

## 先后顺序

1. 李思默保管评测方完整包，其中包含完整输入、作者参考、覆盖表、编题与隔离记录、版本历史和检查证据。
2. 先给许继哲“给许独立复核包”及对应口令。该包只有输入、依据和复核空表，没有作者参考。请许先保存个人首次推导记录，再与李保管的作者参考比较。
3. 处理差异，人工复查新颖性、农业采用范围及非唯一答案；保存修订原因、人员、版本和SHA-256后正式封存。当前候选指纹不等于双人正式封存。
4. 正式封存并准备好统一运行器后，再给金麟哲“给金执行输入包”及其口令。该包只有执行输入、可读展开和字段规范，没有参考、覆盖目标或评分表。输入接收准备不能提前变成留出试跑或调参。

## 解密

使用PowerShell 7.4或更新版本，在本目录运行（系统自带Windows PowerShell 5.1不支持）：

```powershell
pwsh -File ./解密交接包.ps1 -Archive './加密交接包/给许_独立复核_20261020.zip.aesgcm' -OutputDirectory 'E:/独立复核交接'
```

按提示输入对应口令。脚本验证认证标签和归档SHA-256后，在指定目录写出ZIP；拒绝覆盖已有同名文件。请在仓库外解压，评测方完整包不得整包发给开发执行方或提前发给独立复核人。
