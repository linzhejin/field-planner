# 农时窗口

油菜苗期农事规划助手的本地离线验证版。当前页面接入队友提供的规则卡、工程约定和参考案例，以三块模拟地演示需求判断、逐日作业确认、分钟级排程、现场反馈和版本对比。规则名单为 C11、C18、C19、C20、C23、C24、C31；这些原始卡片仍为 `runtime_enabled=false`，页面明确标记“开发验证，适用性待复核”。C 卡是依据，R 卡编号映射和 D01—D12 工程约定分别保存，不混为一组规则。

本版不连接大模型或真实天气服务。规则原文用于展示与追溯，程序判断只由明确编写的条件完成；资料校验、案例通过和模拟排程都不代表农业专家审核、田间验证或独立留出评测。

## 环境与启动

使用 Python 3.12 和 uv：

```powershell
uv sync --locked
uv run python -m nongshi.check_env
uv run streamlit run src/nongshi/app.py
```

浏览器打开终端显示的本地地址。默认样例使用未来一天作为排程起点，避免在当天上午的模拟时段之前才录入计划。左侧编辑地块、需求、分钟数、优先级、用户目标日期、每日逐地块的现场与天气确认，以及单人可用时段。多段时段用分号分隔，例如 `09:00-11:00;13:00-15:00`；相邻时段会合并，重叠输入会报错。保存后生成计划，再从中间栏记录完成、观察、逐日作业条件或人力变化。

右侧显示开始/结束时间、未排入原因、四类状态、规则编号、原文页码和来源指纹。检查任务可在目标苗情未知时生成；维护还需要适用田型、已确认问题和维护需求。每日现场或天气任一为否时，该日不可作业；信息缺失时待确认。工时不足只影响能否排入，不改变作业窗口。任务由一名工人连续完成且不可拆分。

已有计划后若补充积水、沟系、干湿或降雨观察，受影响的已确认“可作业”条件会恢复待确认；明确“不可作业”的记录仍保留。天气确认单独保存来源与快照时间，界面可查看。叶片数可选择“未知”或填写包括 `0` 在内的数值；仅确认维护需求不会被记成新增现场观察。

参考案例入口按 V1、V2、V3 的固定时间重放。V2 保留 A-I、C-I 完成记录和 B-I 时段，把 A-M 移到 10 月 21 日；V3 将 B 地 10 月 20 日标为不可作业，后续日期待确认，同时保留 A-M。页面重新计算结果，案例输入与输出均标为模拟。

重放会建立独立的计划历史。右侧“选择计划”可切回原计划，刷新后仍可在各计划的历史版本间查看。

## 案例审计

运行开发案例并生成机器可读报告：

```powershell
uv run python -m nongshi.cases
```

报告写入 `reports/development_case_report.json`。其中 12 组开发案例按 T12 三个子场景拆为 14 项执行检查；额外 12 组边界案例中 8 项、8 组补充案例中 4 项属于当前可执行范围。其余案例保留为参考项，并注明缺少的知识或产品能力，不计入通过数量。

队友资料位于 `rules/`。运行 `uv run --with-requirements rules/requirements.txt python rules/校验全部资料.py` 可复查两个资料包的文件、来源和内部算例。应用启动时的规则加载器核对 C01—C31、R/C 映射、D01—D12、引用文件 SHA-256 和页码字段；自动测试用开发依赖检查每条页码是否落在本地 PDF 内。

官方 HTML 原件按字节校验；根目录 `.gitattributes` 禁止 Git 自动转换其换行符。不要用编辑器批量重存这些原件。

## 数据、结构与检查

应用数据保存在被 Git 忽略的 `data/local/plans.sqlite3`。旧版 SQLite 计划保留原结构并在页面只读展示；v2 历史使用独立的 `plan_versions_v2` 表。设置 `NONGSHI_DATABASE_PATH` 可指定其他数据库位置。模型服务配置入口在 `.env.example`，当前保持空白。

```text
src/nongshi/     配置、规则读取、状态模型、排程、反馈与 Streamlit 页面
tests/           规则、14 组开发案例、20 组边界/补充案例、SQLite 和页面流程测试
rules/           原始来源、C/R 卡片、工程约定、参考计划和案例
reports/         开发案例执行报告
```

运行自动检查：

```powershell
uv run pytest -q
uv run ruff check .
uv run ruff format --check .
```

测试使用模拟日期、田况和天气，不调用外部服务。开发环境中的 `pypdf` 仅用于核对规则引用页码，不是应用运行依赖。不要提交 `.env`、密钥或本地 SQLite 数据库。
