## 08 评测口径与延期处理

### 评测要证明什么

| 项目 | 目标与记录方式 |
| --- | --- |
| 程序约束 | 参考案例全部通过；逐项计数工时超限、重叠、前置违规和重复任务，目标均为0 |
| 引用支撑 | 对全部被审查农业建议逐条核对原文及适用条件，目标支撑率不低于95%；严重无依据建议为0 |
| 关键缺项 | 缺失案例均追问或待确认，不直接给确定处置；另查完整输入是否被无故拦截 |
| 反馈一致性 | 已完成记录全部保留；新安排满足仍有效约束；移动、移出均有正确原因 |
| 边界稳定性 | 固定结构化输入、规则及天气时，确定性结果一致；模型措辞可不同，关键状态及约束不得自相矛盾 |
| 操作完成 | 至少5名体验者中4人首次独立完成规定流程；记录每人的干预和失败，不只报成功率 |
| 时间与成本 | 分开统计本地排程、端到端响应的样本数、中位数及P95；记录API费用与环境，目标不是成绩 |

30个留出案例分为：正常安排8例、关键缺项6例、工时或前置冲突6例、反馈重排6例、不适用或接口失败4例。初测前锁定分类与规则；接口失败还需C组独立可靠性检查，不混成三组天然同条件的性能优势。

本地排程暂以三块地七天2秒为目标，联网生成以20秒内返回结果或明确失败为目标，均待实测；不沿用需求报告未经论证的统一8秒指标。测试单块、三块和更多地块，不把样本规模宣称为容量上限。模型费按原100至250元预算跟踪，新增支出先由团队决定。
