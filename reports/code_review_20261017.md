## 审查发现与处理

| 级别 | 发现 | 修正 |
| --- | --- | --- |
| 高 | 表单空改动把模拟资料误记为现场观察；仅确认维护需求也会误标来源 | 先归一化输入再比较，需求确认与现场观察分开；合法叶片数 `0` 不再变成未知 |
| 高 | 修改最早/目标日期后，重排仍沿用违反新日期的旧时段 | 保留旧时段前重新检查日期约束 |
| 中 | 新积水、沟系或降雨信息出现后仍沿用旧“可作业”确认 | 仅使受影响地块与日期的旧 `true` 待确认；原有 `false` 保持不可作业 |
| 中 | 秒级反馈产生 `09:00:30` 一类时段，页面却显示到分钟 | 将最早排程时刻向上取整到整分钟 |
| 中 | 案例重放后，原计划留在数据库却无法从页面选回 | 列出各独立计划的最新版本，并处理其他会话追加版本的情况 |
| 中 | 天气确认缺少独立来源和快照时间 | 逐日/逐地块保存 `weather_source` 与 `weather_snapshot_at`；旧记录按默认模拟来源读取 |
| 中 | Windows Git 换行转换导致 S01–S08 原件指纹失败 | 恢复原始字节，使用 `.gitattributes` 禁止自动转换 |
